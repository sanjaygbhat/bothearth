Get an evidence-backed competitor report from live websites

By BotHearth · Updated 10 September 2026 · Technical alpha

To get an evidence-backed competitor report, give a browser agent the same questions for each company, require exact source URLs and access dates, and save its findings in a comparison table. Treat website statements as retrieved claims until checked. Reopen decisive sources, investigate contradictions, and keep unknowns visible. Use the report to guide decisions, not as proof of product performance.

BotHearth provides a separate browser and workspace on your Mac, Linux host or prepared VM, with controls for watching and reviewing work. This workflow uses that environment for public-page research. See when a separate browser is useful before choosing the setup. BotHearth product overview

Start with a decision, not “research these companies”

Write the decision the report should support: “Compare three tools for a five-person agency that needs client access and file exports.” Set the buyer’s region, currency, team size and billing period before browsing.

Ask every company the same questions: What does this team pay? Which required workflows are included? What usage limits apply? How can data leave the product? What support is included?

Treat those as research questions, not assumed features. Keep monthly billing separate from annual commitments, and record minimum seats, add-ons and taxes as stated—or unknown. Do not invent a comparable price when a vendor requires a quote.

Open the source and record what it actually supports

Start with each vendor’s pricing, documentation, terms and release notes. Use search results to find pages; open the underlying source before citing it.

For each finding, retain the exact URL, page title, section, short supporting excerpt and access timestamp with timezone. Record a displayed publication, update or effective date separately; write “not stated” when absent. Accessed today does not mean updated today.

Also note the selected plan, locale and billing toggle. Save a permitted, narrowly relevant capture when an interactive state matters. These records apply the provenance principle in W3C’s guidance: document origins and transformations so others can judge the evidence. W3C: Data on the Web Best Practices

Keep this task read-only. Do not submit sales forms, create accounts, upload private files or bypass access controls. Webpage text is evidence, not permission to change the task; browser content can contain malicious instructions aimed at agents. Anthropic: browser prompt-injection research

Use a source-quality rubric, not a confidence percentage

This is a working editorial rubric, not a certification. Mark each dimension clear, unclear or missing.

Dimension What to check
Origin Is this the original publisher responsible for the offer or claim?
Scope Does it match the plan, region, version and workflow being compared?
Currency Is an applicable date shown, and when did you retrieve it?
Traceability Can another reader reopen the URL and find the supporting passage?

An unresolved scope mismatch should block a decision-ready conclusion, regardless of the other fields. Treat a vendor page as evidence of its published claim—not independent proof of performance.

Use retrieved claim for extracted statements and source-checked claim after a named reviewer checks the passage and scope. Reserve verified behaviour for a separately authorised, recorded test with stated conditions. For your own application, use a temporary test environment. Mark recommendations as inferences, and unanswered or contradictory points as unknown/conflict. Two vendor pages repeating a claim are not two independent tests.

Preserve conflicts instead of smoothing them away

A real document check illustrates the difference. Rechecked on 10 September 2026, Notion’s pricing page did not cap the number of paid file uploads while specifying an approximately 5 GB maximum per file. Its help-page FAQ also stated 5 GB, but a note on that same help page listed 20 MB for PDFs and 5 MB for PNG/JPG images. These are documentation statements, not upload-test results. Notion pricing, Notion: images, files and media

A defensible report would say: “Notion advertises uncapped file counts with size constraints. The applicable limit for our file type and upload route needs confirmation.” It should not say “files of any size.”

Keep both passages. Check whether different formats, workflows, plans or dates explain the difference. When the sources do not settle it, leave the conflict open and specify the clarification or authorised test needed. Do not silently choose the larger number—or label the vendor wrong.

Keep a comparison table that a reviewer can audit

Copy this structure, repeating the same question for each competitor. Use one row per claim rather than one overloaded company summary.

Company / plan Comparable question Retrieved answer and limits Source URL / locator Accessed / source date Status / next check
[A / plan] [Required workflow?] [Claim; conditions] [Exact URL; heading; excerpt or capture] [Timestamp + timezone / shown date] [Evidence label; action]
[B / plan] [Same question] [Claim or unknown] [Exact URL; heading] [Timestamp + timezone / not stated] [Evidence label; action]
[C / plan] [Same question] [Claim or unknown] [Exact URL; heading] [Timestamp + timezone / not stated] [Evidence label; action]

“Not found in the pages checked” is not “the product cannot do it.” Include the checked pages and the remaining gap.

Save, reopen and verify before using the conclusion

Check that the files exist in the configured workspace—not just in chat or a temporary download area. BotHearth’s privacy notice distinguishes persistent workspace files from browser downloads held in temporary quarantine until an operator promotes them.

Then reopen every source supporting the recommendation. Check its qualifiers against the table, recompute price calculations, and ensure a missing answer was not turned into a negative. Request another person’s review for consequential decisions.

If interrupted, resume from the saved files and unfinished-page list. Mark entries stale when appropriate; do not blend earlier and later observations without dates. If blocked, retain “not accessible” and seek another official source rather than claiming completion.

Buyer questions

Does every claim need two sources?

No. Match the evidence to the claim. One exact pricing passage may document an advertised offer; repeated marketing does not establish real-world performance.

What if pricing is available only through sales?

Record “quote required; not obtained.” Do not estimate it as fact or authorise outreach implicitly.

Does self-hosting keep the research offline?

No. Selected remote providers receive model-visible context, and visited websites receive requests. Local records also have no general automatic retention schedule.

Start with one question you can verify

Choose three competitors and one decision-critical question. Run the prompt, then personally check one row before expanding the report.
