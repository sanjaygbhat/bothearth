From a request to a result

  1. Say what you want done. Start with a clear task, the pages or information it should use, and the result you want back.
  2. Watch the agent work. Its computer can open pages, read information, and save files. The activity feed shows the steps alongside its live browser.
  3. Answer when it needs you. Review requests for new destinations and detected sensitive actions. You can also take control of the browser yourself.
  4. Open the result. When the task saves a file, you can open it from the result view. Check the contents and sources before relying on it.

Ordinary allowed browsing and saving a result can proceed without another prompt. Approval detection has limits, so stay nearby for sensitive tasks. See what approvals cover.

Take over when a site needs you

Select Take control to use the agent’s browser yourself. You can complete a sign-in or another step that needs a person, then select Give control back to continue the task.

While you have control, ordinary agent actions and model capture are blocked. The site receives what you type and BotHearth transports that input; never put passwords in the task text. Later page content can become visible to the model after you hand control back.

BotHearth checks the page before returning control. A remaining sensitive-field signal can prevent handback. Ten minutes without input pauses control rather than automatically returning it to the agent. Passkeys and hardware security keys generally do not work inside its browser. Connect your AI account

BotHearth works with the official Codex or Claude Code CLI installed on your computer. In Settings → AI connection, choose one and use its normal sign-in. That connection supplies the AI behind your agent; BotHearth supplies the computer and the task interface.

Your account’s eligibility, usage limits, and charges apply. BotHearth does not include model access and is independent of OpenAI and Anthropic. The setup guide walks through connecting an account; provider requirements cover the details.

Already using another agent interface? The MCP integration guide explains how to connect it to BotHearth’s computer tools. Custom API connections and scheduled tasks use the separate standalone adapter path.

Its computer runs on yours

You run BotHearth on your Mac or Linux computer and open it in a browser. Your agent gets its own browser profile and a workspace for its files. Its saved results stay on that host, where you can open them after the task.

Underneath, containers separate the agent’s browser and shell from your everyday browser. The model connection runs separately on the host, with its own permissions. Remote models still receive the task context they need; running BotHearth locally does not make it offline.

Read the security and privacy guide for the boundaries, or the architecture documentation for the implementation.

What should I expect from this alpha?

BotHearth is intended for one operator and source installation on macOS or Linux. It has no hosted agent service, published npm install path, prebuilt images, or notarized desktop app. Websites can block automation, and third-party rules remain your responsibility.

Task steps and estimated usage can pause work. The harness dollar meter counts computer-tool calls; API estimates use configured prices. Neither is a provider-enforced spending cap. Container hardening and approval gates reduce exposure but cannot make arbitrary unattended browsing safe.
